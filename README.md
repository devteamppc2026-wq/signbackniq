# signbackniq — شاشة النقابة

واجهة برمجة تطبيقات NestJS لإدارة أخبار الشاشة، الشريط الأحمر، وجدولة الفيديوهات. لوحة الإدارة ومعاينة الشاشات موجودين في مشروع `niq-signing-screen-dash`.

## بنية الكود

| المسار | المسؤولية |
| --- | --- |
| `src/app.module.ts` | تجميع وحدات NestJS. |
| `src/core/` | تحميل الإعدادات، توفير اتصال MySQL، وفحص الاتصال وإغلاقه. |
| `src/common/` | قواعد HTTP المشتركة، تحويل الأخطاء، والتحقق من المدخلات باستخدام Zod. |
| `src/modules/auth/` و`users/` | تسجيل الدخول والجلسات، حراسة الصلاحيات، وإنشاء حسابات المحررين. |
| `src/modules/news/` و`ticker/` | الأخبار والأرشيف وإعدادات الشريط الأحمر. |
| `src/modules/screens/` و`video-schedules/` | تسجيل الشاشات وجدولة الفيديو لكل شاشة. |
| `src/modules/display/` | تجميع بيانات العرض من خدمات الأخبار والشاشات والشريط والفيديو. |
| `src/modules/media/` و`feeds/` | رفع وعرض المرفقات والتغذيات الخارجية. |

الطلب يعدّي من الـ controller إلى Zod pipe للتحقق، وبعدها للـ service. الخدمة تستخدم واجهة repository، والوحدة بتربط الواجهة بتنفيذ MySQL باستخدام NestJS injection token. خدمات العرض بتتشارك نفس توقيت الطلب علشان الخبر والشريط والفيديو يتحسبوا على نفس الوقت.

## التشغيل المحلي

```powershell
npm ci
npm run db:setup
npm run seed:admin
npm start
```

اضبط `.env` من `.env.example` قبل الإعداد. افحص الباك إند من `http://127.0.0.1:3100/api/health`. لو لوحة الإدارة المحلية شغّالة على المنفذ 4300، اضبط `APP_ORIGIN=http://127.0.0.1:4300`.

إعداد قاعدة البيانات بينقل حسابات الإدارة القديمة للوحة الجديدة بنفس كلمات المرور. سجّل الدخول من جديد بعد التحديث. لإنشاء مدير جديد شغّل `npm run seed:admin` واكتب البريد وكلمة المرور في التيرمنال. الإدخال مخفي. للتشغيل الآلي استخدم متغيري `SEED_ADMIN_EMAIL` و`SEED_ADMIN_PASSWORD`. تشغيل الأمر تاني لنفس المدير بيحتفظ بكلمة مروره الحالية. الأمر `npm run admin:create` بيشغّل نفس الـ seeder.

من قسم «المستخدمين»، المدير يقدر يضيف حساب محرر ويختار صلاحياته أو يعدّلها بعدين. الصلاحيات هي الإضافة، التعديل، الأرشفة والاسترجاع، والحذف النهائي. المحرر اللي معاه أي صلاحية أخبار يقدر يشوف قائمة الأخبار. إعدادات الشريط والشاشات وجدولة الفيديو وإدارة المستخدمين متاحة للمدير. تغيير الصلاحيات بيسري على الطلبات الجديدة حتى لو المحرر فاتح جلسة بالفعل.

افتح معاينة الشاشة الرئيسية أو أي شاشة مسجّلة من لوحة الإدارة. مسار البيانات لكل شاشة هو `/api/screens/<key>/feed`. لو الباك إند وراء خادم HTTPS وسيط، اضبط `APP_ORIGIN` على عنوان لوحة الإدارة واضبط حد الطلب ومهلة الرفع بما يناسب المرفقات.

## النشر على Vercel

استورد مستودع `devteamppc2026-wq/signbackniq` من صفحة New Project. `vercel.json` بيبني TypeScript ويشغّل واجهة NestJS من Node.js Function واحدة. ضيف القيم التالية في Environment Variables لبيئة Production.

| المتغيرات | القيمة |
| --- | --- |
| `NODE_ENV` | `production` |
| `APP_ORIGIN` | عنوان HTTPS اللي المستخدم بيفتح منه لوحة الإدارة، من غير مسار أو شرطة أخيرة. اعمل rewrites لمسارات `/api/*` و`/uploads/*` من مشروع اللوحة للباك إند عشان الجلسة والطلبات تستخدم نفس عنوان اللوحة. |
| `DB_HOST`، `DB_PORT`، `DB_NAME`، `DB_USER`، `DB_PASSWORD` | بيانات اتصال MySQL. |
| `DB_SSL_MODE` | `required` لاتصال TLS، أو `verify_identity` للتحقق من شهادة وهوية خادم MySQL. مع `verify_identity` حط شهادة CA بصيغة PEM في `DB_SSL_CA`. |
| `CLOUDINARY_CLOUD_NAME`، `CLOUDINARY_API_KEY`، `CLOUDINARY_API_SECRET` | بيانات حساب حفظ الصور والفيديوهات. |

لو قاعدة البيانات جديدة شغّل `npm run db:setup` من جهاز موثوق متصل بيها، واستخدم `npm run seed:admin` لو محتاج تنشئ مدير. بعد النشر اختبر `/api/health` ثم `/api/screens/main/feed`.

Vercel Functions بتقبل طلبات بحجم 4.5 MB افتراضيًا. رفع المرفقات الأكبر من الحد يحتاج رفع مباشر إلى Cloudinary. [حدود Vercel Functions](https://vercel.com/docs/functions/limitations#request-body-size)

## قواعد العرض

- مدة الأخبار النصية والمصوّرة من 5 لـ120 ثانية. مدة الفيديو في لوحة الإدارة بتتحدد تلقائيًا من الملف وتقدر تعدّلها. لو مدة الخبر فاضية، الشاشة تستخدم المدة الافتراضية المسجلة في الإعدادات.
- تاريخ بداية الخبر ونهايته اختياريين. وقت البداية جزء من مدة العرض، ووقت النهاية بيوقف العرض. صفحة الإدارة بتقرأ المواعيد بتوقيت الجهاز وتحفظها بتوقيت UTC.
- الأرشفة بتشيل الخبر من العرض ومن الشريط من غير مسح السجل. الاسترجاع بيحترم حالة النشر والمواعيد القديمة.
- الشريط الأحمر موجود على الشاشة الرئيسية. محتواه نص مخصص أو عناوين مرتبة، لحد 8 أخبار نقابية. العناوين بتظهر طول ما خبرها متاح للعرض. النص المخصص بيظهر لو مفيش عناوين متاحة. النص الفاضي بيخفي الشريط.
- الفيديو ممكن يبقى من غير شاشة، أو لشاشة واحدة، أو لكل الشاشات. لو الجدولة لسه من غير شاشة، الفيديو يفضل مستني التعيين. لو أكتر من فيديو متاح، جدول الشاشة المحددة له الأولوية. بعد كده الأولوية لآخر وقت بداية، ثم لآخر سجل لو البداية اتطابقت.
- الشاشة بتجيب القرار من الخادم كل 3 ثواني تقريبًا، وبتوقف الفيديو عند موعد نهايته حتى لو الاتصال اتقطع. الفيديو بيشتغل من غير صوت وبيتكرر لحد نهاية مدته. جدولة العرض مش محتاجة عملية خلفية منفصلة.

## واجهة البرمجة

| المسار | الوظيفة |
| --- | --- |
| `GET /api/screens/:key/feed` | بيانات الشاشة، الأخبار المتاحة، الفيديو الحالي، توقيت الخادم، وإعدادات العرض. |
| `GET /api/display?screen=main` | نفس بيانات الشاشة مع الطقس ومواقيت الصلاة بالشكل اللي يناسب الواجهة الحالية. |
| `GET /api/news/petroleum` و`GET /api/prices/petroleum` | التغذيات الخارجية الموجودة. |
| `POST /api/auth/login` و`GET /api/auth/me` و`POST /api/auth/logout` | جلسة الإدارة. |
| `GET/POST /api/admin/users` و`PUT /api/admin/users/:id/permissions` | إنشاء محرر وعرض الحسابات وتعديل صلاحيات الأخبار. |
| `GET/POST /api/admin/news` و`PUT /api/admin/news/:id` | عرض الأخبار وإضافتها وتعديلها. |
| `POST /api/admin/news/:id/archive` و`POST /api/admin/news/:id/restore` | الأرشفة والاسترجاع. |
| `GET/PUT /api/admin/ticker` | نص الشريط ومعرّفات الأخبار المختارة. |
| `GET/POST /api/admin/screens` | تسجيل الشاشات وعرضها. |
| `GET/POST /api/admin/video-schedules` و`PUT/DELETE /api/admin/video-schedules/:id` | إضافة جدول، تعديله أو إلغاؤه. |
| `POST /api/admin/uploads` و`POST /api/admin/uploads/video` | رفع الصورة كحقل `image` أو الفيديو كحقل `video` باستخدام multipart. |

طلبات الإدارة تحتاج جلسة صالحة. الطلبات اللي بتغير البيانات تحتاج كمان قيمة `union_csrf` في هيدر `X-CSRF-Token` وعنوان مطابق للإعداد. ملفات Cloudinary بتتقدّم من عنوان محلي مع دعم طلبات أجزاء الفيديو. الصور لحد 5 ميجابايت، والفيديو لحد 25 ميجابايت.

شغّل `npm run build` للبناء و`npm test` للاختبارات.
